## 1. 운영 점검

- 워커 큐 지연, 실패·재시도·dead-letter 수
- Google OAuth 만료/철회, Gmail API quota 및 polling 지연
- Calendar 생성 성공·중복·불확실 상태
- 푸시 구독 만료, 발송 실패와 앱 내 알림 backlog
- LLM 토큰·비용, Langfuse trace 누락 및 오류
- DB 용량, 백업 성공과 복구 가능성

## 2. 비밀정보와 데이터

OAuth 토큰, 세션 키, API 키, VAPID private key는 비밀 저장소에서 관리하고 주기적으로 교체한다. 관찰 로그에는 메일 본문, 첨부파일, OAuth 토큰, 푸시 endpoint 원문을 포함하지 않는다. 계정 연결 해제 시 토큰을 폐기하고 작업을 중지한다.

## 3. 사고 대응

잘못된 일정 자동 등록이나 조직 간 데이터 노출이 확인되면 자동화를 즉시 비활성화하고 관련 run, message ID, event ID, trace ID를 보존한다. 대상 사용자에게 영향과 복구 방법을 안내한다. Calendar 정정은 권한 있는 담당자가 확인 후 수행하며 감사 이력에 남긴다.

## 4. 사용자 통제

사용자는 Google 연결, 자동 감지, 웹 푸시 구독을 각각 끌 수 있어야 한다. 자동화 비활성화와 OAuth 철회는 진행 중 작업의 추가 Gmail 검색·Calendar 생성을 막는다. 이미 성공한 Calendar 이벤트는 기록을 보존하고 삭제는 별도 사용자 명령으로 처리한다.

## 5. 운영 tripwire와 대응

| 신호 | 대응 |
|---|---|
| 동일 단계 오류가 연속 3회 발생 | 해당 연결의 polling/외부 쓰기를 일시 중지하고 원인 점검 |
| Calendar 생성률 또는 중복률 급변 | 자동 Calendar write 차단, 실패·정상 표본 비교 |
| 실행당 비용이 설정 상한 도달 | 추가 모델 호출 정지, checkpoint와 부분 결과 보존 |
| 새 도메인 또는 scope 밖 도구 요청 | 호출 거부, 보안 로그/경보 생성 |
| 푸시 실패 증가 | Calendar 생성은 유지, push만 재시도하고 앱 내 알림 backlog 확인 |
| 센서 통과율·추출 품질의 유의한 하락 | 자동화 범위를 제한하고 이전 템플릿/프롬프트 버전으로 되돌림 |

알림 기준값은 파일럿 기준선을 측정한 뒤 설정한다. 임계값을 넘었을 때 자동 조치는 외부 쓰기를 안전하게 멈추는 방향으로 제한한다.

## 6. 실패를 영구 개선으로 전환

장애마다 입력 fixture, 실행 ID/trace ID, 영향, 실패 계층, 복구 결과를 남긴다. 동일 실패를 재현하고 가장 적합한 가이드·센서·루프·메모리·권한·관찰 변경을 추가한 다음 재현 케이스와 회귀 검증을 수행한다. 임시 프롬프트 수정만으로 장애를 종료 처리하지 않는다.
