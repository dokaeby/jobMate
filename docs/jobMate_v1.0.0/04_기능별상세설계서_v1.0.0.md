## 2. 업무 템플릿 실행

### 입력

템플릿 ID와 버전, 필수 텍스트/파일 참조, 실행 옵션. API가 권한과 schema를 검증하고 `WorkflowRun`을 만든다.

### 처리

LangGraph가 고정된 그래프를 실행한다. 각 노드는 제한된 도구만 사용하고 JSON schema로 출력을 검증한다. 실패는 해당 노드에 기록하고 정책상 재시도 가능한 오류만 다시 실행한다.

### 검수 기준

- 실행 상세에 노드별 대기·진행·완료·오류 상태가 표시된다.
- 사용자는 본인이 접근 가능한 조직의 결과만 볼 수 있다.
- 승인 단계는 승인자 결정 전 후속 노드를 진행하지 않는다.

## 3. Gmail 일정 자동화

### 검색

사용자 OAuth 연결과 활성화된 일정 자동화 규칙이 있어야 한다. Gmail API로 처리 시점 이후의 메일을 검색한다. 초기 검색 기간과 polling 간격은 운영 설정값으로 두며 사용자에게 연결 상태와 마지막 검색 시각을 표시한다.

### 추출·검증

에이전트 출력 필드: `summary`, `title`, `start_at`, `end_at`, `timezone`, `location`, `attendees`, `source_message_id`, `source_url`, `confidence`. 날짜와 시간대를 정규화하며, 종료가 시작보다 빠르거나 필수 시간이 모호하면 생성하지 않는다. confidence threshold는 파일럿 검증 후 설정한다.

### Calendar 등록

유효한 일정은 Calendar API에 자동 생성한다. 원본 메시지 ID와 계정 ID 조합을 unique 처리 키로 사용한다. 성공 응답의 event ID를 저장한다. API timeout은 생성 실패로 단정하지 않고 Calendar에서 idempotency marker를 조회한 후 재시도한다.

### 푸시·이동

Calendar 저장이 확인되면 즉시 웹 푸시 알림을 큐에 넣는다. 클릭 URL은 `https://mail.google.com/mail/u/{account}/#all/{messageId}` 형식의 원본 메일 링크를 사용한다. 웹 푸시의 `notificationclick`에서 링크를 새 창 또는 기존 창으로 열고, 구독 권한이 없으면 앱 내 알림함에 같은 알림을 남긴다.

### 예외

| 경우 | 처리 |
|---|---|
| 정보가 불명확/신뢰 점수 부족 | `needs_review`로 보류, 자동 등록·푸시 미발송 |
| 이미 처리된 원본 메시지 | 중복 생성을 건너뛰고 기존 이벤트 참조 |
| OAuth 취소/철회 | 감지 중단, 사용자에게 연결 오류 표시 |
| Gmail 일시 오류 | backoff 재시도 후 실패 큐 기록 |
| Calendar 생성 결과 불명 | marker/event 검색 후 중복 없이 복구 |
| Calendar 등록 후 푸시 실패 | 이벤트 유지, 푸시만 재시도, 앱 내 알림 표시 |
| 원본 메일 삭제 또는 접근 권한 없음 | 푸시는 열리지만 Google이 접근 오류를 표시할 수 있음; 앱 알림에 발신자/제목 최소 표시 |

## 4. 접근성·사용성

알림 권한 요청은 맥락과 효용을 설명한 뒤 사용자 동작으로 요청한다. 권한이 거부되어도 Calendar 연동과 일정 자동 등록은 동작하며 앱 내 알림 목록에서 이력을 확인한다. 상태는 색상만으로 표시하지 않는다.
