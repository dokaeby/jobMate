# 05. 내부 기능 통합 — calendar-agent / skillRadar / Codex 제공자

기존 `calendar-agent`, `skillRadar` 프로젝트의 기능을 하네스 내부 워크플로로 이식한 내용.

## 1. 모델 제공자와 debug/release 라우팅

- `ModelConfig.provider`: `openai_compat`(기본) | `codex`
- `CompositeLLM`이 provider별 클라이언트로 디스패치
- `CodexResponsesLLM`: `~/.codex/auth.json`의 ChatGPT 구독 OAuth 토큰 사용.
  `chatgpt.com/backend-api/codex/responses`에 SSE 스트리밍 필수(`stream:true`).
  액세스 토큰 만료 시 `auth.openai.com/oauth/token`으로 refresh 후 auth.json 갱신.
- `Settings.mode`:
  - `debug` — 모든 역할/티어가 `default_model`(gemini-3.5-flash-lite)로 강제
  - `release` — default 티어는 gemini, important 티어는 `important_model`(codex, `gpt-5.6-sol`)
- 역할별 오버라이드 `role_models`는 양쪽 모드에서 유지.

## 2. calendar-agent 이식 (`gmail_calendar` v0.2.0)

멀티채널 공통 소스 컨텍스트: `source_provider` ∈ `gmail|slack|telegram`,
`source_id`, `thread_id`, `source_url`, `message_text`.

단계: `extract(LLM) → validate(결정적) → conflict_check(Calendar 검색) →
register(멱등) → notify`

- Slack: `POST /api/v1/webhooks/slack` — `X-Slack-Signature` HMAC 검증,
  5분 타임스탬프 윈도우, `url_verification` 챌린지, 채널 allowlist
- Telegram: `POST /api/v1/webhooks/telegram` — secret-token 헤더 검증, 봇 메시지 무시
- 수신함: `message_extractions` 테이블, `(provider, source_id)` 멱등,
  `processing_status` pending/processed/failed + 재시도 백오프(최대 5회)
- 워커(`_automation_loop`, `JOBMATE_WORKER_INTERVAL_SECONDS`):
  pending 메시지 → run 생성·동기 실행, due `notification_jobs` 발송,
  `gmail_calendar` 자동화 활성 시 주기적 Gmail 폴링, KST 06시 이후 radar 일일 수집
- `scheduled_events`: provider-aware event_key, status, version
- Calendar 충돌/자기중복은 `CalendarClient.search_events` 사전 검색으로 판별.
  타임아웃 후 불확실 쓰기는 marker 검색으로 복구(이벤트 재생성 없음).
- 알림 실패해도 캘린더 링크 보존, 사전 알림은 `notification_jobs`에 예약.

신규 엔드포인트: `/webhooks/slack`, `/webhooks/telegram`, `/messages`,
`/messages/{provider}/{id}/retry`, `/listeners/status`, `/events`,
`/notification-jobs`, `/gmail-calendar/poll`(어댑터 필요)

## 3. skillRadar 이식 (`skill_radar` v0.1.0)

단계: `collect → dedupe → summarize(LLM, default 티어) → rank → approve(사람) → publish`

- `radar_collect`: `queries.json`의 플랫폼별 GitHub Search 쿼리,
  `GitHubClient` 프로토콜(GitHubAPI 실구현 + FakeGitHub). README는
  `Accept: application/vnd.github.raw`로 fetch, base64 폴백.
- `radar_dedupe`: `full_name` 중복, fork, archived 제외.
- `radar_summarize`: `RepoSummary`(en/zh/ko 요약, taxonomy+confidence,
  summary_status). content_hash 캐시로 재호출 방지, 실패 시 메타데이터 폴백.
  LLM 실패는 audit 기록 후 계속 진행.
- `radar_rank`: stars + 일일 증가량 + 라이선스 + taxonomy 신뢰도 점수.
- `radar_publish`: 승인 전 reject면 스냅샷 미작성. `radar_snapshots`/
  `radar_items`에 일별 플랫폼 스냅샷 저장(같은 날 재실행 시 갱신).

엔드포인트: `GET /radar/trending?platform&date&lang`, `GET /radar/dates`,
`POST /radar/refresh {platforms, force}` (플랫폼당 run 생성)

Web Push: `GET /push/vapid-key`, `POST /push/subscribe|unsubscribe`,
`GET /sw.js` — gmail_calendar notify 단계에서 `webpush` 어댑터가
저장된 구독 전체로 발송(VAPID_PRIVATE_KEY 필요, 404/410 구독 자동 삭제).

## 4. 코딩 도구 어댑터 (`tools/coding.py`)

implementer 단계를 LLM API 대신 실제 코딩 CLI로 실행할 수 있다.
`JOBMATE_CODING_TOOL` ∈ `none|claude|codex|antigravity|opencode`.

| 도구 | 바이너리 | 헤드리스 호출 |
|---|---|---|
| claude | `claude` | `claude -p --output-format text --permission-mode bypassPermissions` |
| codex | `codex` | `codex exec --sandbox workspace-write` |
| antigravity | `agy` | `agy --print=<prompt> --dangerously-skip-permissions --sandbox` |
| opencode | `opencode` | `opencode run --auto [--model <m>] <prompt>` |

- `JOBMATE_CODING_MODEL`로 모델 지정 가능(비우면 각 CLI 기본값).
  opencode 기본 provider(rapid-mlx 로컬)가 꺼져 있으면
  `JOBMATE_CODING_MODEL=opencode/big-pickle` 같은 무료 모델 지정 필요.
- `_run_cmd`는 자식 프로세스의 `PWD`를 작업 디렉터리로 맞춘다 —
  opencode가 `$PWD` 기준으로 파일을 쓰므로 필수.

- `AgentSpec.coding_tool`이 설정되면 `_run_llm_stage`가 LLM 대신 CLI를 호출.
- 작업 디렉터리: `JOBMATE_CODING_WORKSPACE` 지정 시 해당 경로, 미지정 시
  `data/workspaces/<run_id>`에 git repo를 자동 생성(빈 초기 커밋).
- 실행 후 `workspace_diff()`가 `git diff HEAD` + untracked 파일의
  new-file diff를 수집해 `ChangeProposal.diff`로 반환 → 기존
  auto_checks(git apply --check, 시크릿 스캔)와 리뷰 파이프라인 그대로 통과.
- CLI 비정상 종료는 `CodingToolError` → 단계 실패 → 기존 재시도/에스컬레이션.
- CLI 선택은 `jobmate run --coding-tool <name>` 또는 env로.
- 주의: `coding_workspace`를 실제 레포로 지정하면 도구가 작업 트리를 직접
  수정한다. diff는 수집만 하고 적용은 기존 승인 흐름을 따른다.

## 5. 어댑터

| 프로토콜 | 실구현 | fake |
|---|---|---|
| GitHubClient | `radar/github.py: GitHubAPI` | `FakeGitHub` |
| CalendarClient | `adapters/google.py: GoogleCalendar` | `FakeCalendar` |
| GmailClient | `adapters/google.py: GoogleGmail` | `FakeGmail` |
| Notifier | `adapters/local.py: LoggingNotifier` + `adapters/push.py: WebPushNotifier` | `FakeNotifier` |

Google 연동: `JOBMATE_GMAIL_TOKEN_PATH`/`JOBMATE_CALENDAR_TOKEN_PATH`에
토큰 JSON 경로를 설정하면 `_default_adapters`가 실구현을 주입한다.
토큰 발급은 `jobmate google-auth gmail|calendar` —
`--credentials <credentials.json>`(calendar-agent와 같은 OAuth client
파일) 또는 `--client-id/--client-secret` 지정, loopback + state 검증,
refresh token을 0600 권한으로 저장. 토큰 파일은 calendar-agent의
`token_gmail.json`/`token_calendar.json`(google-auth Credentials
형식)과 호환되므로 그대로 재사용 가능. 헤더는 RFC2047/mojibake 복원,
Calendar 검색은 nextPageToken 전체 페이지 순회(calendar-agent 포팅).
Calendar 멱등 마커는 `extendedProperties.private.jobmate_marker`에 기록.

## 6. 상용 전환(Django) 시 이관 대상

- `api/app.py`의 엔드포인트/워커 → Django views + Celery/RQ 태스크
- `store/db.py` → Django ORM/PostgreSQL (스키마는 그대로 이관 가능)
- LangGraph 체크포인터 → PostgresSaver
- 워크플로/함수/센서는 프레임워크 비의존이라 그대로 재사용

## 7. Vercel 배포 / PostgreSQL

- `app.py`(루트)가 Vercel Python entrypoint — `src/`를 sys.path에 추가 후
  `jobmate.api.serverless:app`(`create_app()` 인스턴스)을 노출.
- DB: `Store`는 인자가 `postgres://`/`postgresql://` DSN이면 psycopg3 +
  `SCHEMA_PG`로 PostgreSQL을, 아니면 SQLite 파일을 사용.
  `JOBMATE_DATABASE_URL` 또는 Vercel Postgres의 `POSTGRES_URL`(자동 인식)이
  있으면 PG 사용, 없으면 `JOBMATE_DB_PATH` SQLite.
  SQL은 `?`→`%s`, `INSERT OR IGNORE`→`ON CONFLICT DO NOTHING`으로 번역되는
  단일 코드베이스.
- 서버리스에서는 lifespan의 자동화 스레드를 띄우지 않음(`VERCEL` env 감지).
  대신 `GET|POST /api/v1/cron/tick`이 `_automation_loop` 1사이클을 실행 —
  `vercel.json`의 cron이 주기 호출. `CRON_SECRET` env가 있으면
  `Authorization: Bearer <CRON_SECRET>` 검증(Vercel Cron이 자동 부착).
- 주의: Vercel Hobby 플랜 cron은 하루 1회 제한 — 분 단위 폴링이 필요하면
  외부 스케줄러(GitHub Actions 등)로 tick을 호출하거나 Pro 플랜 필요.
- Google 토큰 파일 경로는 env로 주입 — 서버리스에서 파일 기반 토큰은
  ephemeral FS라 재발급되거나 DB/secret 저장소로 옮겨야 함(미구현).

## 8. 이메일 3줄 요약 카드 (`/api/v1/email/check`)

- 외부 스케줄러(cron-job.org 등)가 30분마다 `POST /api/v1/email/check` 호출.
  본문 `{"limit": 5, "query": "in:inbox"}` — limit 최대 20.
- `adapters["gmail"]`(GoogleGmail)로 최근 메일을 읽고 메시지별 LLM 3줄 요약을
  생성해 `email_summaries` 테이블에 upsert. 결과는 `GET /api/v1/email/summaries`
  로 조회하며 Gmail Checker 뷰가 우선 표시(없으면 message_extractions 폴백).
- 인증: `CRON_SECRET`/`JOBMATE_CRON_SECRET` 설정 시 `Authorization: Bearer` 또는
  `?secret=` 파라미터 필요. 미설정이면 오픈(로컬 개발용).
- Gmail API 오류 시 502 + `{"ok": false, "error": ...}` 반환.
