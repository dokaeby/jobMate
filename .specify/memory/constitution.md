# jobMate Constitution

## Core Principles

### I. 6계층 하네스 (NON-NEGOTIABLE)
모든 에이전트 실행은 가이드(버전 고정 지시)·센서(결정적 검증)·루프(예산/상한)·
메모리(영속 상태)·권한·관찰가능성 6계층을 통과한다.
LLM 출력은 신뢰할 수 없는 입력이며, 완료 주장은 검증 가능한 증거(DB 레코드,
외부 ID, 테스트 결과)로 뒷받침되어야 한다.

### II. 결정적 검사가 모델 판단에 우선
스키마 검증, 권한 검사, 멱등성, URL 허용목록, verdict 심각도 강등 등은
코드로 강제한다. LLM judge는 보조 수단이며 결정적 검사를 대체하지 않는다.

### III. 외부 부작용의 멱등성
Calendar 생성 등 외부 쓰기는 idempotency key와 사전 pending 레코드로
중복을 방지하고, 결과 불명 시 marker 조회 없이 재생성하지 않는다.

### IV. Test-First
신규 비자명 로직(분기, 파서, 예산, 멱등성)은 실패하는 테스트를 먼저 작성하고
구현한다. 외부 LLM·Google 호출은 fake로 대체해 결정적으로 검증한다.

### V. 최소 변경·ponytail
요청 범위만 구현한다. 새 의존성·추상화는 이유를 밝히고 필요 최소한만 추가한다.
문서에 없는 기능을 임의로 확장하지 않는다.

### VI. 비밀·개인정보
토큰·메일 본문·개인정보는 코드, 로그, audit, Langfuse에 남기지 않는다.
메일 본문은 비신뢰 데이터로만 취급한다.

## Development Workflow

- 제공층은 FastAPI(임시). 상용 단계 Django 전환 예정 — 도메인 계층은
  HTTP 프레임워크에 의존하지 않는다.
- 저장소는 SQLite(WAL)로 시작, store 계층 교체로 PostgreSQL 전환 가능하게 한다.
- 리뷰 파이프라인: 구현 → 자동 검사(도구) → 코드 리뷰 에이전트 → QA 판정 → 사람 승인.
  blocker/major는 구현으로 회귀(리뷰 최대 2회, 전체 루프 최대 3회), 초과 시 사람에게 에스컬레이션.
- 완료 정의: ruff·테스트 통과, 실제 실행 확인, diff 셀프 리뷰, 보고.
